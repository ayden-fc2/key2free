# herome-a

## 回测系统目标架构

当前项目后续要把通用回测系统和其中的通用信号系统规整为如下阶段化实现。目标是让每个策略单独维护自己的页面、信号函数、买入操作、卖出操作；回测框架只保证通用性，并允许每个策略自己配置回测时每天的参数传递。

## 信号系统或者回测系统信号预计算阶段

指定交易日或者回测日期内每天：

输入给具体策略：全市场所有股票当日T以前200交易日宽表数据

具体策略输出给信号系统或者回测系统：T日爆出信号的股票

## 回测系统逐日回测阶段

回测系统有观望池、持仓池、资金量、交易记录

指定交易日或者回测日逐日执行：

### 1. 卖出

回测系统输入给具体策略：这时候持仓池的股票至少已经持仓一天，符合T+1卖出条件，把持仓池的股票所有信息，包含持仓份额、持仓时间、股票T日（包含T日）以前200交易日的所有宽表数据（注意不要引入未来数据），以及回测系统当前的状态，包含当前日期、资金量情况、过去的交易记录等

具体策略输出给回测系统：持仓池的票是否卖出以及卖出多少手

最后回测系统执行

注意这里为了方便卖出条件，把T日数据传递进了策略，策略的买入函数需要自己处理未来函数，例如开盘价卖出就只用开盘价，盘中达到价格卖出就用最高价和最低价。务必强调给策略的卖出函数不要用T日宽表的MA等指标数据，避免引入未来函数。

实际上这里传入的宽表数据T日前是全的，T日就只传入开盘收盘最高最低和分钟线数据，从根本上杜绝策略乱用MA等

### 2. 买入

回测系统输入给具体策略：执行今天卖出后的资金池情况（乐观估计今日卖出的资金都能得到利用用以买入）、信号池、交易记录、观望池的所有股票及其包含T日的以前200交易日宽表。

具体策略函数传回给交易系统：观望池中哪些票要买入，哪些票继续保留在信号池，哪些票从观望池中删除

注意这里为了方便买入条件，把T日数据也传入了策略的买入函数，策略的买入需要自己处理未来函数，例如开盘价买入就只用到开盘价，盘中价格达到了买入否则继续观望或者超出观望时长退出就只用到T日最高价最低价，务必强调给策略的买入函数不能用T日宽表的MA等指标数据，避免引入未来函数。

实际上这里传入的宽表数据T日前是全的，T日就只传入开盘收盘最高最低和分钟线数据，从根本上杜绝策略乱用MA等

### 3. 选信号

回测系统输入给具体策略的选信号函数近日的信号票以及其过去包含T在内的过去200交易日的宽表数据、系统的资金池情况、持仓池情况、本次回测交易记录

具体策略输出给回测系统要加入信号池的股票

注意这里模拟的是T收盘结束，拿到T全部数据后分析去预判T+1的信号，因此这里传入的T日的宽表数据是全的，策略函数可以用。

## 后续实现准备

后续重构时，通用回测框架应只负责数据装载、交易日推进、资金和仓位维护、订单记录、快照记录；具体策略负责信号判断、观望池处理、买入判断、卖出判断和策略参数解释。

为避免未来函数，回测系统需要区分两类数据视图：

1. `history_view`：截止T-1的完整宽表数据。
2. `today_market_view`：T日只包含开盘、最高、最低、收盘和分钟线等交易中可观察数据。

只有在“收盘后选信号”阶段，策略才能使用T日完整宽表指标。
