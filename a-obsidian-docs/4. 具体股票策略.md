# 具体股票策略

每个具体股票策略由三个互不干扰的模块组成：

- 信号策略
- 入场策略
- 出场策略

三类模块分离后，同一信号可以复用不同入场/出场规则做实验，也可以在保持交易规则不变时替换信号逻辑。

## 信号策略

信号策略判断单只股票在交易日 `T` 是否爆出买入信号。

输入：

| 参数 | 意义 |
| --- | --- |
| `code` | 股票代码，例如 `sh.600000`。 |
| `trade_date` | 当前交易日 `T`。 |
| `universe.trade_date` | `mart.universe_daily` 中该股票池记录对应的交易日。 |
| `universe.code_name` | 股票名称。 |
| `universe.security_type` | 证券类型。 |
| `universe.list_status` | 上市状态。 |
| `universe.industry` | 行业名称。 |
| `universe.industry_classification` | 行业分类体系。 |
| `bars_1d_qfq` | 该股票在 `mart.bar_1d_qfq` 中 `T` 及以前所有交易日的前复权日线历史，按交易日升序排列。 |
| `bars_1d_qfq[].trade_date` | 历史序列中每根日线的交易日，范围为 `<= T`。 |
| `bars_1d_qfq[].open` | 对应交易日的前复权开盘价。 |
| `bars_1d_qfq[].high` | 对应交易日的前复权最高价。 |
| `bars_1d_qfq[].low` | 对应交易日的前复权最低价。 |
| `bars_1d_qfq[].close` | 对应交易日的前复权收盘价。 |
| `bars_1d_qfq[].preclose` | 对应交易日的前收盘价。 |
| `bars_1d_qfq[].volume` | 对应交易日的成交量。 |
| `bars_1d_qfq[].amount` | 对应交易日的成交额。 |
| `bars_1d_qfq[].turn` | 对应交易日的换手率。 |
| `bars_1d_qfq[].tradestatus` | 对应交易日的交易状态。 |
| `bars_1d_qfq[].pct_chg` | 对应交易日的涨跌幅。 |
| `bars_1d_qfq[].pe_ttm` | 对应交易日的滚动市盈率。 |
| `bars_1d_qfq[].pb_mrq` | 对应交易日的市净率。 |
| `bars_1d_qfq[].ps_ttm` | 对应交易日的滚动市销率。 |
| `bars_1d_qfq[].pcf_ncf_ttm` | 对应交易日的滚动市现率。 |
| `bars_1d_qfq[].is_st` | 对应交易日是否 ST。 |
| `bars_1d_qfq[].adjust_factor_value` | 对应交易日使用的复权因子。 |

`bars_1d_qfq` 是信号策略的主要行情输入，策略应基于这组 `T` 及以前的完整历史序列计算趋势、均线、关键位、波动率等特征。需要 T 日行情时，直接从 `bars_1d_qfq` 中取 `trade_date == T` 的记录。

输出：

- 当前统一输出 `bool`。
信号策略函数标准返回 `SignalDecision`：

| 字段 | 说明 |
| --- | --- |
| `triggered` | 是否在 `T` 日爆出买入信号。 |
| `min_stop_loss` | 最低止损参考价。 |
| `reference_take_profit` | 参考止盈价。 |
| `signal_atr30` | 信号日使用的 ATR30 值。 |
| `ideal_buy_price` | 策略认为合理的理想买入价格上限或参考价。 |
| `max_watch_days` | 爆信号后最多观望交易日数量。 |

后续所有策略都应按该结构返回。服务层兼容旧的 `True`/`False`，但新策略不再以 bool 作为正式规范。

约束：

- 只能使用 `T` 及以前的数据。
- 所有预处理结果必须按 `as_of_date` 读取或写入。
- 不负责资金、仓位、成交、止盈止损等交易动作。
- 不直接查询 DuckDB，不绕过信号系统传入的上下文读取数据。
- 不修改输入数据，不产生持久化副作用。
- 当 `bars_1d_qfq` 为空、缺少 `trade_date == T` 的记录或历史行情不足时，应返回 `SignalDecision(triggered=False)` 或按策略自身规则保守处理。

## 入场策略

入场策略处理观望池中的股票，决定是否在当前交易日买入。

输入：

- 观望池记录
- 当前交易日 `T`
- `T` 及以前的行情和预处理数据
- 当前资金、仓位上限和已有持仓

输出：

- 买入
- 继续观望
- 移出观望池

约束：

- 今日刚进入观望池的股票不能当日买入，保证 `T+1` 交易。
- 买入金额不超过总资产的 `1/3`。
- 买入股数必须是 100 的整数倍。
- 需要调用回测撮合边界判断，停牌、一字涨停等不可买场景不能成交。

## 出场策略

出场策略处理当前持股池，决定是否在当前交易日卖出。

输入：

- 持股记录
- 当前交易日 `T`
- `T` 及以前的行情和预处理数据
- 买入成本、持有天数、当前收益等持仓状态

输出：

- 卖出
- 继续持有

约束：

- 今日刚买入的股票不能当日卖出，保证 `T+1` 交易。
- 需要调用回测撮合边界判断，停牌、一字跌停等不可卖场景不能成交。
- 不负责发现新买入信号。

## 推荐策略接口

后续实现时，建议保持三类策略接口显式分离：

```python
class SignalStrategy:
    def evaluate(self, code: str, trade_date: date, context: StrategyContext) -> SignalResult:
        ...


class EntryStrategy:
    def evaluate(self, watch_item: WatchItem, trade_date: date, context: StrategyContext) -> EntryDecision:
        ...


class ExitStrategy:
    def evaluate(self, position: Position, trade_date: date, context: StrategyContext) -> ExitDecision:
        ...
```

`StrategyContext` 应只暴露按 `as_of_date` 安全读取的数据访问方法，避免策略模块绕过上下文直接读取未来数据。

## 策略目录结构和接入准则

每个具体策略在 `backend/strategies/` 下使用独立目录，目录名应和策略注册名保持一致或明显对应。

标准目录结构：

```text
backend/strategies/
  demo/
    __init__.py
    strategy.py
```

`strategy.py` 至少提供三个函数：

```python
def demo_signal_strategy(context: StockDataContext) -> SignalDecision:
    ...


def demo_entry_strategy(*args, **kwargs) -> int:
    ...


def demo_exit_strategy(*args, **kwargs) -> int:
    ...
```

接入准则：

- 在 `backend/app/services/strategy_registry.py` 的 `STRATEGY_REGISTRY` 注册策略。
- 注册项必须包含唯一的 `name`、信号策略函数、入场策略函数和出场策略函数。
- 前端用于选择策略的名称必须与后端注册名一致。
- 后续策略列表 API 或前端硬编码策略名，都应以注册表为准。
- 信号系统默认向信号策略传入 `mart.bar_1d_qfq` 中 `T` 及以前的前复权历史，不需要策略单独声明。
- 具体策略需要 MA、MACD、布林带、成交量、金叉等指标时，可以先在策略内独立维护；当算法稳定且多个策略都会复用时，再沉淀到 `backend/app/indicators/`。
- 前端当日信号页会基于信号结果批量拉取数据库中的全量 `StockDataContext`，用于渲染日 K、MACD 和成交量图；策略输出只需要给出是否爆信号。
- 策略函数只实现策略判断逻辑，不负责 API 参数解析、股票池查询、数据加载、资金管理或回测撮合。
- 入场策略和出场策略当前接口尚未最终确定，临时可返回 `-1` 作为占位；确定回测模块后再补充标准输入输出。
