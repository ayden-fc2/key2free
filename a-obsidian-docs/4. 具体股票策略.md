# 具体股票策略

每个具体股票策略由三个互不干扰的模块组成：

- 信号策略
- 入场策略
- 出场策略

三类模块分离后，同一信号可以复用不同入场/出场规则做实验，也可以在保持交易规则不变时替换信号逻辑。

入场和出场策略有框架默认实现（`signal_close` 限价买入、阶梯止盈止损引擎，见 [[3.  事件驱动的回测系统#日级运行逻辑]]）。策略也可以在注册表中选择 `next_open` 等入场模式；大多数策略只需要实现信号策略并给出止损/止盈数组。

## 信号策略

信号策略判断单只股票在交易日 `T` 是否爆出买入信号。

### 输入

信号系统按 [[2. 信号系统#传给信号策略的数据]] 的约定，向策略传入单只股票 `T` 及以前最近 **400 根**宽表行（`tushare.stock_daily_technical`，按交易日升序，含 `T` 日）。历史不足 400 根的股票由信号系统直接跳过，策略不需要再处理这种情况。

宽表行已包含前复权 OHLC、基础信息和全部预计算指标列（MA、ATR、均量、BOLL、MACD、RSI、KDJ、K 线结构比例等，完整口径见 [[1. 数据资产#技术指标宽表]]）。策略应直接使用这些列，只在策略内部计算宽表没有覆盖的派生特征（例如滚动线性拟合斜率、结构低点识别）。

需要 `T` 日行情时，取窗口最后一行。

### 输出

信号策略函数标准返回 `SignalDecision`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `triggered` | `bool` | 是否在 `T` 日爆出买入信号。 |
| `signal_close` | `float` | `T` 日前复权收盘价，即确认买入价。 |
| `stop_losses` | `list[float]` | 止损位数组，按档位顺序排列。 |
| `take_profits` | `list[float]` | 止盈位数组，与 `stop_losses` 等长、按档位一一对应。 |
| `max_watch_days` | `int` | 爆信号后最多观望交易日数量。 |
| `extras` | `dict \| null` | 策略自定义参考值（ATR、结构位等），框架透传，仅用于复盘。 |

### 约束

- 只能使用 `T` 及以前的数据。
- 所有预处理结果必须按 `as_of_date` 读取或写入。
- 不负责资金、仓位、成交、止盈止损执行等交易动作；止盈止损只以价位数组形式声明。
- 不直接查询 DuckDB，不绕过信号系统传入的窗口数据读取数据。
- 不修改输入数据，不产生持久化副作用。
- 窗口内关键列存在 `null`（停牌缺口、指标未就绪）时，应返回 `SignalDecision(triggered=False)` 或按策略自身规则保守处理。

## 入场策略

入场策略处理观望池中的股票，决定是否在当前交易日买入。

**框架默认实现**：以 `signal_close` 为限价买单——开盘价 `<= signal_close` 按开盘价成交；否则 `low <= signal_close <= high` 按 `signal_close` 成交；否则继续观望，超过 `max_watch_days` 移出观望池。

注册为 `next_open` 的策略跳过限价触发判断，使用下一个交易日的开盘价买入；`T+1` 指下一个交易日，不是自然日。

覆写时的输入输出：

- 输入：当日 OHLC、观望池记录（含完整 `SignalDecision`）。
- 输出：`-1` 表示继续观望（由框架按 `max_watch_days` 控制移除）；正数表示按该价格买入。

约束：

- 今日刚进入观望池的股票不能当日买入，保证 `T+1` 交易。
- 仓位由框架按风险敞口统一计算：单笔最坏止损亏损 `<= 总资产 * risk_per_trade`（默认 2%），取满足约束的最大百股仓位；策略可叠加单票市值上限，最终受上限和可用现金共同封顶。详见 [[3.  事件驱动的回测系统#成本和仓位]]。
- 撮合边界（停牌、一字板不可交易）由框架统一判断。

## 出场策略

出场策略处理当前持股池，决定是否在当前交易日卖出。

**框架默认实现**：阶梯止盈止损引擎——按持仓当前档位检查 `stop_losses[level]`（先）和 `take_profits[level]`（后）；止损触发全部卖出；非最后一档止盈触发卖出一半（向上取整到百股）并升档；最后一档止盈触发全部卖出；跳空穿越价位时按开盘价成交。详见 [[3.  事件驱动的回测系统#通用阶梯止盈止损引擎]]。

覆写时的输入输出：

- 输入：当日 OHLC、持仓记录（买入日期、买入价、当前数量、当前档位、完整 `SignalDecision`）。
- 输出：不卖、按价格部分卖出（含数量）、按价格全部卖出的结构化结果。

约束：

- 今日刚买入的股票不能当日卖出，保证 `T+1` 交易。
- 撮合边界（停牌、一字跌停不可卖）由框架统一判断。
- 不负责发现新买入信号。

## 策略目录结构和接入准则

每个具体策略在 `backend/strategies/` 下使用独立目录，目录名应和策略注册名保持一致或明显对应。

标准目录结构：

```text
backend/strategies/
  demo/
    __init__.py
    strategy.py
```

接入准则：

- 在 `backend/app/services/strategy_registry.py` 的 `STRATEGY_REGISTRY` 注册策略。
- 注册项必须包含唯一的 `name` 和批量信号函数 `batch_signal_strategy`；`required_columns` 声明策略需要的宽表列；代码级预过滤 `code_filter` 可选；入场/出场函数可选（缺省使用框架默认实现）。
- 前端用于选择策略的名称必须与后端注册名一致；策略列表以注册表为准。
- 信号系统默认传入固定 400 根宽表窗口，策略不需要单独声明窗口长度。
- 具体策略需要的指标优先用宽表列；宽表没有且多个策略复用的算法，再沉淀到 `backend/app/indicators/`（`trend/`、`volume/`、`patterns/`）。
- 前端当日信号页会基于信号结果批量拉取全量历史用于渲染图表；策略输出只需要给出 `SignalDecision`。
- 策略函数只实现策略判断逻辑，不负责 API 参数解析、股票池查询、数据加载、资金管理或回测撮合。
