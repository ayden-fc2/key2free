> 注意本文的T代表交易日结束后拿到所有信号

本项目用于个人选股决策，目标是中国A股，功能包含
* 数据资产
* 信号系统
* 事件驱动的回测系统（避免未来函数）
* 具体股票策略（每种策略解藕，每种策略包括信号策略、入场策略、出场策略三个互不干扰模块）

### 1. 数据资产

使用duckdb存储的大A历史股票数据，见 ./data/ 目录。
当前数据刷新由后端接口触发：`POST /api/v1/data-assets/stocks/refresh`。
接口会创建 `source_update` 后台任务并立即返回 `task_id`；前端或调用方通过 `GET /api/v1/data-assets/source-update-task?task_id=...` 轮询任务日志和状态，也可以通过 `POST /api/v1/data-assets/source-update-task/stop` 请求停止。

`./data/refresh/` 目录保留数据更新流程说明，`./data/refresh/refresh.py` 目前不是实际入口。
详见 [[1. 数据资产]] 和 `../data/refresh/README.md`。

### 2. 信号系统

针对单日是否存在买入信号进行处理，输入日期T，输入策略模块，输出出信号的股票。
当前信号系统使用 `mart.bar_1d_qfq` 的前复权日 K。该视图使用当前维护到的 `adjust_factor` 计算前复权价格，暂不做 `as_of_date=T` 的复权因子版本化；因此它适合个人复盘、看盘口径和策略原型验证，但严格无未来函数回测暂不保证复权因子口径。
其中信号系统主要工作是：
* 把数据资产预处理，包括每只股票的趋势分布、关键位等，避免策略模块重复计算（用时取，没有则计算存储，注意用as_of_date避免未来函数）
* 宏观筛选，过滤掉不适合策略执行的行业趋势/大盘指数趋势/股票类型
* 逐支股票地拿到T以前的数据资产和预处理结果，然后调用信号策略模块得知今天该不该买
* T日内所有股票执行完毕后输出爆出信号的股票

### 3. 事件驱动的回测系统

输入股票策略后，使用信号系统和具体回测功能的完整回测系统，从设计上避免未来函数。买入费率buy_fee_bps  = 5，卖出sell_fee_bps = 10

系统包括：
* 资金池，默认初始为100000
* 每笔仓位，总资产的1/3，买入 <= 1/3 * 总资产，且股数为100倍数的股票
* 观望池，存储爆出信号准备买入的票
* 持股池，存储当前持有的股票
* 交易记录，记录买入订单、卖出订单、每日快照用于统计计算

系统运行逻辑：
* 输入信号策略、入场策略、出场策略
* 从2019年1月开始，逐日按顺序执行（当前输入日期为T）
	* 处理观望池，按照入场策略，排除今日进入的股票（T+1交易），符合则买入（5bps），不符合的按照入场策略处理继续观望或者删掉，更新观望池、持股池、资金、买入订单
	* 处理持股池，排除掉今日买入的股票（T+1交易），剩余股票按照出场策略，符合则卖出（10bps），更新持股池、资金、卖出订单
	* 把T、信号策略输入信号系统，拿到T日的信号，确保过滤掉持股池中已有的票，放入观望池
	* 记录每日快照
* 执行到最新日期后结束，后续统计交易记录，得到逐年交易笔数、盈亏比、年化利率、最大回撤、胜率等

注意：
* 撮合边界不能完全忽略，判断当天是否可交易（注意按照涨跌停价格要有误差容忍）
	* 停牌：volume == 0 或 open/high/low/close 缺失，不能买卖
	* 一字涨停：open = high = low = close = 涨停价，不能买卖
	* 一字跌停：open = high = low = close = 跌停价，不能买卖
	* 普通涨停：close >= 涨停价附近，能买
	* 普通跌停：close <= 跌停价附近，能卖

详见 [[3.  事件驱动的回测系统]]。

### 4. 具体股票策略

每个具体股票策略包含信号策略、买入策略、卖出策略
信号策略接收到单个股票的T及以前的数据和预处理数据，按照特定规则决定是否爆信号

详见 [[4. 具体股票策略]]。
