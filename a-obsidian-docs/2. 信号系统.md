# 信号系统

信号系统负责在指定交易日 `T` 上执行某个已注册策略的信号策略函数，输出当日爆出买入信号的股票列表。当前后端入口为 `POST /api/v1/signals/daily`，服务层为 `SignalService`，策略注册表为 `STRATEGY_REGISTRY`。

> [!note] 数据来源
> 信号系统统一从数据资产层宽表 `tushare.stock_daily_technical` 读取前复权行情、基础信息和预计算技术指标（字段口径见 [[1. 数据资产#技术指标宽表]]）。旧 `mart.bar_1d_qfq` / `mart.universe_daily` / `source.*` 已废弃。
>
> 宽表前复权价格使用"目标水位内该股票最新复权因子"，暂不做 `as_of_date=T` 的复权因子版本化。信号查询会把行情严格截断到 `trade_date <= T`，适合个人复盘、看盘口径和策略原型验证；严格无未来函数回测暂不保证复权因子口径。

## 信号系统输入输出规范

输入：

- `trade_date`：交易日 `T`（回测预计算时为一组交易日），格式为 `YYYY-MM-DD`。
- `strategy_name`：策略注册名，例如 `demo`。

后端会根据 `strategy_name` 从策略注册表取得：

- 代码级预过滤函数 `code_filter`（可选，板块/交易所等静态条件，用于减少历史加载量）。
- 信号策略函数 `batch_signal_strategy`（必须，按股票批量评估）。
- 策略所需宽表列 `required_columns`（框架基础列之外的部分）。
- 入场策略函数、出场策略函数（可选，缺省使用框架默认实现，供回测系统使用）。

### 传给信号策略的数据

信号系统按固定窗口向策略传入单只股票的宽表历史：

- **固定回看窗口 400 根**：每只股票传入 `T` 及以前最近 400 根宽表行（含 `T` 日），按交易日升序。
- **历史不足 400 根的股票直接跳过**，不调用策略（新股、长期停牌恢复初期都被保守排除）。
- 宽表中指标列可能为 `null`（如停牌缺口附近），策略应保守处理为不出信号。

传入行即宽表行，核心字段分组（完整列表见 [[1. 数据资产#技术指标宽表]]）：

| 分组 | 字段示例 |
| --- | --- |
| 主键 | `trade_date`、`code`（`sz.000001` 形式）、`ts_code` |
| 前复权行情 | `qfq_open`、`qfq_high`、`qfq_low`、`qfq_close`、`qfq_pre_close` |
| 原始行情 | `open/high/low/close`、`vol`、`amount`、`pct_chg` |
| 基础信息 | `name`、`industry`、`area`、`pe`、`pb`、`total_share` 等 `bak_basic` 字段、`is_st` |
| 波动/量能 | `atr_5/14/30`、`atr_pct_*`、`avg_volume_5/10/20`、`volume_ratio_*`、`vwap_*` |
| 趋势 | `ma_5/10/20/30/60/120`、`bias_*`、`ma_slope_*`、`er_10/20/60` |
| 通道/动量 | `boll_*`、`macd_dif/dea/hist_12_26_9`、`rsi_*`、`roc_*`、`kdj_*` |
| K 线结构 | `body_range_ratio`、`upper_shadow_range_ratio`、`lower_shadow_range_ratio`、`body_atr14_ratio`、`range_atr14_ratio`、`overnight_return` |

策略应**优先使用宽表中已预计算的指标列**（MA、ATR、均量、K 线结构比例等），避免在策略内重复计算；只有宽表没有覆盖的派生特征（例如 MA30 滚动线性拟合斜率、结构低点识别）才在策略内基于已传入的列计算。所有这些列都只由 `T` 及以前的数据滚动得出，不引入未来函数。

### 信号策略输出：`SignalDecision`

信号策略函数标准输出为 `SignalDecision` 结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `triggered` | `bool` | 是否在 `T` 日爆出买入信号。 |
| `signal_close` | `float` | `T` 日前复权收盘价。默认入场模式下也是确认买入价；若策略注册为次日开盘买入，则仅作为信号日参考价。 |
| `stop_losses` | `list[float]` | 止损位数组，按生效顺序排列（支持移动止损）。当前 demo 为单档 `[stop_loss]`。 |
| `take_profits` | `list[float]` | 止盈位数组，按生效顺序排列（支持移动止盈）。当前 demo 为单档 `[take_profit]`。 |
| `max_watch_days` | `int` | 爆信号后最多观望交易日数量。当前 demo 为 `1`，配合次日开盘入场。 |
| `extras` | `dict \| null` | 策略自定义参考值（如 `signal_atr30`、结构低点 L4 等），框架透传、不参与撮合，便于复盘。 |

约定：

- `stop_losses` 与 `take_profits` 一一对应同一"档位"：持仓初始在第 0 档；触发第 0 档止盈后卖出一半并升到第 1 档（止损、止盈同时切换）；触发当前档止损全部卖出；触发最后一档止盈全部卖出。档位语义由回测系统的通用阶梯引擎统一执行，见 [[3.  事件驱动的回测系统]]。
- 数组长度不限于 2，框架按数组长度通用处理；两个数组长度必须一致。
- 旧字段 `min_stop_loss` / `reference_take_profit` / `ideal_buy_price` / `signal_atr30` 废弃，分别由 `stop_losses[0]`、`take_profits` 数组、`signal_close`、`extras` 取代。
- 服务层不再以 `True`/`False` 作为新策略的合法返回。

### 信号系统整体输出

| 字段 | 说明 |
| --- | --- |
| `trade_date` | 本次执行的交易日。 |
| `strategy_name` | 本次执行的策略名。 |
| `universe_count` | `T` 日股票池数量（宽表 `T` 日行数）。 |
| `signal_count` | 爆出信号的股票数量。 |
| `signals` | 爆出信号的股票列表，每项包含股票代码、名称、`universe`（宽表 `T` 日基础信息）和 `signal` 决策对象。 |

当日信号列表返回后，前端会再调用 `POST /api/v1/signals/stock-contexts`，输入信号股票代码列表，批量取得这些股票的全量历史用于渲染日 K、MACD、成交量等图表。该上下文不受当日信号运行日期截断，仅用于前端展示。

> [!warning]
> 信号策略只能使用 `T` 及以前已经可获得的数据。后续预处理、缓存、财报、行业、宏观等数据接入时，必须带 `as_of_date` 语义，不能读取最新全量结果替代历史视角。

## 信号系统执行流程

1. API 层接收 `trade_date`（或回测传入的交易日数组）和 `strategy_name`。
2. 服务层根据 `strategy_name` 从策略注册表读取策略定义；如果策略不存在，返回错误。
3. 从宽表取得区间内出现过的股票代码，先用策略的代码级预过滤 `code_filter` 缩小集合，再按批分组（控制内存）。
4. 逐股一次性加载"区间起点前 400 根 + 区间内"的宽表行（列式结构，框架基础列 + 策略声明列）。
5. 对该股票在区间内的每个目标交易日做批量评估：窗口不足 400 根的日期跳过；其余日期调用策略信号函数得到 `SignalDecision`。与交易日相关的成分条件（如 `is_st`、名称含 ST）由策略在信号函数内基于宽表列判断。
6. 收集 `triggered == true` 的结果，生成各交易日信号列表。
7. 返回 `universe_count`、`signal_count` 和 `signals`，供前端展示，也供回测系统复用。

逐股批量评估是标准执行方式：每只股票的历史只加载一次、指标序列只展开一次，区间内所有交易日共享，这是信号预计算性能的关键。单日查询是"交易日数组长度为 1"的特例。

当前 `demo` 策略已注册，信号策略包含普通 A 股成分筛选、N 字结构筛选、K 线形态筛选、盈亏比过滤，并在回测中使用下一个交易日开盘入场，详见 [[strategies/demo|demo 策略]]。
