# 信号系统

信号系统负责在指定交易日 `T` 上执行某个已注册策略的信号策略函数，输出当日爆出买入信号的股票列表。当前后端入口为 `POST /api/v1/signals/daily`，服务层为 `SignalService`，策略注册表为 `STRATEGY_REGISTRY`。

## 信号系统输入输出规范

输入：

- `trade_date`：交易日 `T`，格式为 `YYYY-MM-DD`。
- `strategy_name`：策略注册名，例如 `demo`。

后端会根据 `strategy_name` 从策略注册表取得：

- 信号策略函数。
- 入场策略函数。
- 出场策略函数。

信号系统默认会为每个信号策略准备 `mart.bar_1d_qfq` 中 `T` 及以前的前复权历史，不需要策略单独声明。

注意：当前 `mart.bar_1d_qfq` 使用维护到最新的 `source.adjust_factor` 生成前复权价格，信号查询会限制日 K 为 `trade_date <= T`，但暂不对复权因子做 `as_of_date=T` 版本化。因此当前信号系统的股票池和行情日期边界是按 `T` 截断的，适合个人复盘和策略原型验证；严格无未来函数回测暂不保证复权因子口径。

传给单只股票信号策略函数的标准输入为 `StockDataContext`。它是更高层级的单股数据上下文，不只服务于信号策略，也可以作为后续回测渲染、均线绘制、MACD 绘制和其他指标 utils 的统一数据基准：

| 参数 | 意义 |
| --- | --- |
| `code` | 股票代码，例如 `sh.600000`。 |
| `trade_date` | 当前交易日 `T`。 |
| `universe.trade_date` | `mart.universe_daily` 中该股票池记录对应的交易日。 |
| `universe.code_name` | 股票名称。 |
| `universe.security_type` | 证券类型。 |
| `universe.list_status` | 上市状态。 |
| `universe.industry` | 行业名称。 |
| `universe.industry_classification` | 行业分类体系。 |
| `bars_1d_qfq` | 该股票在 `mart.bar_1d_qfq` 中 `T` 及以前所有交易日的前复权日线历史，按交易日升序排列。 |
| `bars_1d_qfq[].trade_date` | 历史序列中每根日线的交易日，范围为 `<= T`。 |
| `bars_1d_qfq[].open` | 对应交易日的前复权开盘价。 |
| `bars_1d_qfq[].high` | 对应交易日的前复权最高价。 |
| `bars_1d_qfq[].low` | 对应交易日的前复权最低价。 |
| `bars_1d_qfq[].close` | 对应交易日的前复权收盘价。 |
| `bars_1d_qfq[].preclose` | 对应交易日的前收盘价。 |
| `bars_1d_qfq[].volume` | 对应交易日的成交量。 |
| `bars_1d_qfq[].amount` | 对应交易日的成交额。 |
| `bars_1d_qfq[].turn` | 对应交易日的换手率。 |
| `bars_1d_qfq[].tradestatus` | 对应交易日的交易状态。 |
| `bars_1d_qfq[].pct_chg` | 对应交易日的涨跌幅。 |
| `bars_1d_qfq[].pe_ttm` | 对应交易日的滚动市盈率。 |
| `bars_1d_qfq[].pb_mrq` | 对应交易日的市净率。 |
| `bars_1d_qfq[].ps_ttm` | 对应交易日的滚动市销率。 |
| `bars_1d_qfq[].pcf_ncf_ttm` | 对应交易日的滚动市现率。 |
| `bars_1d_qfq[].is_st` | 对应交易日是否 ST。 |
| `bars_1d_qfq[].adjust_factor_value` | 对应交易日使用的复权因子。 |

`bars_1d_qfq` 是信号策略的主要行情输入，策略应基于这组 `T` 及以前的完整历史序列计算趋势、均线、关键位、波动率等特征。需要 T 日行情时，直接从 `bars_1d_qfq` 中取 `trade_date == T` 的记录。

后续通用指标算法可以沉淀在 `backend/app/indicators/`，供具体策略和回测模块复用。当前仅作为预留目录；复杂指标可以先在具体策略内独立维护，确认稳定后再抽取为通用算法：

```text
backend/app/indicators/
  trend/      # MA、EMA、MACD、布林带等趋势指标
  volume/     # 成交量、成交额、换手率等量能指标
  patterns/   # 金叉、死叉、K 线形态等模式识别
```

信号策略函数输出：

- `True`：该股票在 `T` 日爆出买入信号。
- `False`：该股票在 `T` 日不爆信号。

信号系统整体输出：

| 字段 | 说明 |
| --- | --- |
| `trade_date` | 本次执行的交易日。 |
| `strategy_name` | 本次执行的策略名。 |
| `universe_count` | `T` 日股票池数量。 |
| `signal_count` | 爆出信号的股票数量。 |
| `signals` | 爆出信号的股票列表，每项包含股票代码、名称和 `universe`。 |

当日信号列表返回后，前端会再调用 `POST /api/v1/signals/stock-contexts`，输入信号股票代码列表，批量取得这些股票在数据库中的全量 `StockDataContext`。该上下文不受当日信号运行日期截断，用于前端渲染日 K、MACD、成交量等图表。

> [!warning]
> 信号策略只能使用 `T` 及以前已经可获得的数据。后续预处理、缓存、财报、行业、宏观等数据接入时，必须带 `as_of_date` 语义，不能读取最新全量结果替代历史视角。

## 信号系统执行流程

1. API 层接收 `trade_date` 和 `strategy_name`。
2. 服务层根据 `strategy_name` 从策略注册表读取策略定义；如果策略不存在，返回错误。
3. 查询 `mart.universe_daily`，取得 `T` 日股票池。
4. 查询 `mart.bar_1d_qfq` 中股票池内所有股票在 `T` 及以前的前复权历史，并按股票代码分组。
5. 逐只股票构造 `StockDataContext`。
6. 逐只股票调用对应的信号策略函数。
7. 收集返回 `True` 的股票，生成当日信号列表。
8. 返回 `universe_count`、`signal_count` 和 `signals`，供前端展示，也供后续回测系统复用。
9. 前端根据 `signals` 中的股票代码批量请求全量 `StockDataContext`，左侧展示信号列表，右侧通过可复用组件渲染选中股票的日 K、MACD 和成交量图。

当前 `demo` 策略已注册，信号策略包含普通 A 股成分筛选、MA20/MA30 趋势筛选、MA30 结构筛选和 MACD 不利多背离过滤，用于验证完整信号流程和策略接入规范。
