# 事件驱动的回测系统

本文记录当前 README 中的回测设计，后续实现应以这里为独立设计页继续补充。

## 目标

输入一个完整股票策略后，回测系统按交易日顺序驱动信号、入场、出场和资金变动，从设计上避免未来函数。

默认交易成本：

- 买入费率 `buy_fee_bps = 5`
- 卖出费率 `sell_fee_bps = 10`

## 核心对象

- 资金池：默认初始资金 `100000`。
- 每笔仓位：最多使用总资产的 `1/3` 买入，且成交股数必须是 100 的整数倍。
- 观望池：保存已经爆出信号、等待入场策略确认的股票。
- 持股池：保存当前持有的股票。
- 交易记录：记录买入订单、卖出订单和每日快照，用于后续统计。

## 日级运行逻辑

输入信号策略、入场策略、出场策略后，从 2019 年 1 月开始逐交易日执行。当前交易日记为 `T`。

1. 处理观望池。
   - 排除今日刚进入观望池的股票，保证 `T+1` 交易。
   - 对剩余股票调用入场策略。
   - 符合买入条件时按 `5bps` 成本买入。
   - 不符合条件时按入场策略决定继续观望或移除。
   - 更新观望池、持股池、资金和买入订单。
2. 处理持股池。
   - 排除今日刚买入的股票，保证 `T+1` 交易。
   - 对剩余股票调用出场策略。
   - 符合卖出条件时按 `10bps` 成本卖出。
   - 更新持股池、资金和卖出订单。
3. 调用信号系统。
   - 输入 `T` 和信号策略。
   - 获取 `T` 日爆出信号的股票。
   - 过滤掉持股池中已有的股票。
   - 将新信号加入观望池。
4. 记录每日快照。

执行到最新日期后，基于交易记录统计逐年交易笔数、盈亏比、年化利率、最大回撤、胜率等指标。

## 撮合边界

回测不能完全忽略当天是否可交易，至少需要处理以下边界：

- 停牌：`volume == 0` 或 `open/high/low/close` 缺失时不能买卖。
- 一字涨停：`open = high = low = close = 涨停价` 时不能买卖。
- 一字跌停：`open = high = low = close = 跌停价` 时不能买卖。
- 普通涨停：`close >= 涨停价附近` 时仍允许买入。
- 普通跌停：`close <= 跌停价附近` 时仍允许卖出。

涨跌停价判断需要保留误差容忍，避免浮点数或行情四舍五入导致误判。

## 避免未来函数的约束

- 信号系统在 `T` 日只能读取 `T` 及以前已经可获得的数据。
- 入场使用观望池中的历史信号，今日新增信号不能当日买入。
- 出场不能处理今日刚买入的股票。
- 预处理和缓存必须带 `as_of_date`，不能用最新全量结果覆盖历史视角。
- 每日快照应在当日处理完成后记录，后续统计只读取交易记录和快照。
