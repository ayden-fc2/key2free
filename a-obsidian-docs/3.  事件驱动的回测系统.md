# 事件驱动的回测系统

本文记录回测系统的目标实现约定。目标是复用信号系统，按交易日顺序驱动信号、观望、买入、持仓、卖出和资金变化，严格避免未来函数，同时保证回测一次在分钟级完成。

> [!note] 数据来源
> 交易日来自 `tushare.trade_cal`，行情统一来自宽表 `tushare.stock_daily_technical`（前复权 OHLC 用 `qfq_*` 字段）。旧 `mart.bar_1d_qfq` / `source.trade_calendar` 已废弃。
>
> 宽表前复权价格使用"目标水位内最新复权因子"，暂不做复权因子 `as_of_date=T` 版本化；因此当前版本适合个人复盘和策略原型验证，严格无未来函数回测暂不保证复权因子口径。

## 前端入口

回测统计页面提供以下参数：

- 回测周期：默认 `2019-01-01` 到最新水位。
- 初始仓位：默认 `100000` 元。
- 策略：默认 `demo`。

点击开始回测后，后端创建一条回测任务记录。回测任务允许重复创建，同一个参数可以多次运行，所有回测结果表都用 `task_id` 区分。

每个回测任务固定执行 50 轮随机撮合。信号预计算只执行一次；50 轮共享同一个 `task_id` 和同一批预计算信号，买入订单、卖出订单和每日快照通过 `run_no` 区分不同随机撮合结果。

## 任务流程与性能架构

回测分三个阶段，SQL 只出现在前两个阶段：

1. **信号预计算（一次）**：调用信号系统的逐股批量评估（见 [[2. 信号系统#信号系统执行流程]]），对回测区间内所有交易日预计算信号，写入 `meta.backtest_signal`。每只股票的宽表历史只加载一次。
2. **行情装载（一次）**：收集所有爆出过信号的股票代码，把这些股票在回测区间内的日线（`qfq_open/high/low/close`、`vol`、涨跌停判定所需字段）一次性批量载入内存，构建 `code -> 按日期索引的列式数组`。爆信号股票通常只有几百只，内存占用很小。
3. **50 轮纯内存撮合**：每轮从初始资金重新开始，逐日撮合全程不再查询 DuckDB；订单和每日快照先在内存累积，每轮结束后批量写入结果表。

> [!warning] 性能红线
> 撮合主循环（交易日 × 轮次）内禁止任何 SQL 查询和逐行 INSERT。历史实现每日每轮查询 `get_bar_map` 并逐行写快照，导致一次回测运行数小时；新架构必须保持"预计算 → 装载 → 内存撮合 → 批量落库"的结构。

## 回测结果表

### `meta.backtest_signal`

保存预计算信号：

- `task_id`：回测任务 ID。
- `trade_date`：信号日。
- `strategy_name`：策略名。
- `code`、`code_name`：股票代码和名称。
- `universe_json`：信号日宽表基础信息摘要。
- `signal_json`：标准化信号对象，包含 `triggered`、`signal_close`、`stop_losses`、`take_profits`、`max_watch_days`、`extras` 字段。

### `meta.backtest_buy_order`

保存买入订单：

- `task_id`、`run_no`、`trade_date`、`code`、`code_name`。
- `buy_price`、`quantity`、`amount`、`fee`、`cash_after`。
- `signal_json`：触发本次观望/买入的信号对象。

### `meta.backtest_sell_order`

保存卖出订单：

- `task_id`、`run_no`、`trade_date`、`code`、`code_name`。
- `sell_price`、`quantity`、`amount`、`fee`、`cash_after`。
- `buy_date`、`buy_price`、`pnl`、`sell_reason`（`stop_loss` / `take_profit_partial` / `take_profit_final`）、`level`（触发时档位）。

### `meta.backtest_daily_snapshot`

保存每日快照：

- `task_id`、`run_no`、`trade_date`。
- `total_asset`、`cash`、`holding_market_value`。
- `holding_count`、`watch_count`。
- `holding_json`：持仓池明细。
- `watch_json`：观望池明细。

## 日级运行逻辑

回测维护三个池：

- 现金池：初始值来自前端输入。
- 持仓池：保存代码、名称、买入日期、买入价格、当前数量、当前档位 `level`、`stop_losses`、`take_profits`、信号对象。
- 观望池：保存代码、名称、加入日期、加入交易日序号、`signal_close`、`max_watch_days`、信号对象。

每天 `T` 按照固定顺序执行：

1. **处理持仓池（卖出）**。
   - 跳过当日刚买入的股票，保证不做当日买当日卖。
   - 读取当日内存行情；撮合边界判断不可卖则跳过。
   - 执行通用阶梯止盈止损引擎（见下节）。
2. **处理观望池（买入）**。
   - 使用 `任务随机种子 + run_no + trade_date` 打乱观望池执行顺序，降低单次随机顺序造成的偶然性。
   - 跳过当日刚进入观望池的股票，保证信号日不能当日买入。
   - 超过最长观望时长的股票（信号日后第 `max_watch_days + 1` 个交易日起）直接移出观望池，不再尝试买入。
   - 执行入场判定：默认以 `signal_close` 为限价买单；若策略注册为 `next_open`，则按下一个可处理交易日的开盘价买入。策略可以通过注册表选择入场模式。
   - 成交则按资金规则计算数量，更新买入订单、现金池、持仓池和观望池。
3. **把当日新信号加入观望池**。
   - 已在持仓池或观望池中的股票不重复加入。
   - 新信号只进入观望池，不允许当天买入。
4. **写入每日快照**（内存累积，轮末批量落库）。

### 通用阶梯止盈止损引擎

持仓带档位 `level`（初始 0），`stop_losses[level]` / `take_profits[level]` 为当前生效价位。

> [!important] 止损口径（2026-06 起的目标规范，随黄金柱战法接入实现）
> 止损统一改为**收盘价确认**：当日收盘价跌破当前档止损位才触发，以**收盘价**卖出；盘中影线刺破不算。止盈维持盘中触及成交。该口径对所有策略生效。切换前的回测任务（task 1~15，盘中触发口径）与切换后不可直接对比，历史策略需重跑基线。

单日检查顺序：

1. **止盈（盘中）**：记 `tp = take_profits[level]`，当 `open >= tp` 或 `high >= tp` 时触发，成交价 = `max(open, tp)`（高开按开盘价成交）：
   - 若 `level` 不是最后一档：卖出一半，股数向上取整到 100 股（如 300 股卖 200 股；仅 100 股则全部卖出，持仓清空）；然后 `level += 1`，止损、止盈同时切换到下一档。
   - 若 `level` 是最后一档：全部卖出。
2. **止损（收盘确认）**：若当日收盘价 `close <= stop_losses[level]`（止盈减半后用升档后的止损位判断），按收盘价全部卖出。
3. **持仓时限（可选，按策略配置 `max_holding_days`）**：到期日收盘仍持有则按收盘价全部卖出，卖出原因记 `time_stop`。
4. 都未触发则继续持有。

该引擎由回测系统统一实现，策略只需在 `SignalDecision` 中给出 `stop_losses` / `take_profits` 数组；需要特殊出场逻辑的策略可以在注册表中覆写出场函数，但默认不需要。

### 撮合边界

判断当天是否可交易（保守口径）：

- 停牌：`vol <= 0` 或 OHLC 缺失，不能买卖。
- 一字板：`open == high == low == close`（一字涨停、一字跌停或全天单一价格的极端无流动性），双向不可交易。
- 普通涨停/跌停：盘中存在价格区间，可按上述引擎规则成交。

## 成本和仓位

- 买入费率 `buy_fee_bps = 5`。
- 卖出费率 `sell_fee_bps = 10`。
- **风险敞口定仓**：单笔最坏情况亏损不超过当日估算总资产的 `2%`（`risk_per_trade`，可按策略在注册表覆写），取满足该约束的最大仓位。风险参考价由策略注册项 `risk_price_basis` 决定，默认为实际买入价；demo 使用信号日收盘价：

```text
risk_reference_price = buy_price 或 signal_close
risk_per_share = risk_reference_price - stop_losses[0]
quantity = floor(总资产 * 2% / risk_per_share / 100) * 100
quantity = min(quantity, 单票市值上限能买入的最大百股数, 可用现金能买入的最大百股数（含手续费）)
```

- 没有第一止损位、或风险参考价已不高于第一止损位（风险无法界定）时不买入。
- 策略可配置 `position_cap_fraction` 作为单票市值上限；demo 为总资产的 `1/4`，即 `buy_price * quantity <= total_asset * 1/4`。
- 总资产在买入时点用当日开盘价估算持仓市值（开盘价此刻已知，无未来函数）。
- 数量恒为 100 股整数手。止损越近仓位越大（被现金和单票上限封顶），止损越远仓位越小，单笔风险被统一锚定在 2% 以内。

仓位模式按策略注册选择（随黄金柱战法接入实现）：

- `risk`（默认）：上述 2% 风险定仓，demo 使用。
- `fraction`：总资产固定比例（如黄金柱战法的 1/3），百股取整、现金封顶。

入场模式同样按策略注册选择：默认为 `signal_close` 限价；demo、黄金柱战法和姜神战法使用"次日开盘市价买入"。这里的次日指下一个交易日，例如周五信号对应下周一正常交易日开盘。停牌/一字板按撮合边界视为不可交易。

## 策略函数规范

策略注册包含：

- **信号函数（必须）**：逐股批量评估形式，输入单只股票的宽表列式数据和目标评估位置，返回 `SignalDecision`；见 [[4. 具体股票策略#信号策略]]。
- **入场函数（可选）**：默认使用框架的 `signal_close` 限价买入语义；覆写时输入当日 bar（OHLC/量）和观望池记录，返回成交价格或 `None`（继续观望）。
- **出场函数（可选）**：默认使用框架的阶梯止盈止损引擎；覆写时输入当日 bar 和持仓记录（含档位），返回结构化卖出动作（原因、价格、数量、是否升档）或 `None`（继续持有）。

阶梯引擎补充约定：盘中部分止盈升档后，**当日收盘**即用升档后的止损位做收盘确认——单日最多两笔卖出（盘中止盈减半 + 收盘止损剩余仓位）。部分止盈时买入费用按卖出比例分摊进各笔卖出的 `pnl`。

## 避免未来函数的约束

- 信号系统在 `T` 日只读取 `T` 及以前的数据（固定 400 根回看窗口）。
- 回测先处理历史持仓和历史观望池，再把 `T` 日新信号加入观望池。
- 当日新信号不能当日买入，当日新买入不能当日卖出。
- 股票池使用宽表 `T` 日行（历史每日快照），不使用最新静态股票表覆盖历史。
- 止损、止盈、买入价全部在信号日 `T` 收盘后即可确定（由 `SignalDecision` 携带），撮合日只做价格触达判断，不回头读取信号日之后的数据修改决策。
- 宽表前复权使用"水位内最新复权因子"，暂不做 `as_of_date=T` 版本化，是当前已知且接受的口径妥协。
